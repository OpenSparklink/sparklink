# sparklink-python

Python bindings for libsparklink, the SparkLink userspace library.

Uses ctypes to call into `libsparklink.so` (the C FFI layer generated by cbindgen).

## Requirements

- Python >= 3.9
- `libsparklink.so` built from the Rust workspace (`cargo build --release -p libsparklink`)

## Installation

```bash
pip install -e bindings/python/
```

## Tests

From the workspace root, run the unit tests and ABI conformance checks:

```bash
PYTHONPATH=bindings/python python3 -m unittest discover -s bindings/python/tests -v
```

The conformance tests require `cc`, `rustc` and the matching kernel source
checkout at `../linux`. To use another checkout, set `SPARKLINK_KERNEL_UAPI`
to its `include/uapi/linux/sparklink_ioctl.h` file. Missing compilers or a
missing header fail the tests; they do not silently skip ABI validation.

The tests compile the actual kernel C UAPI, public C header and Rust UAPI
types, and compare every Python structure's fields, sizes, alignments and
member offsets. A C write into a guarded Python connection-info buffer also
checks the SSAP and credit fields. These tests need no devices, Cargo package
downloads or installed `libsparklink.so`. CI pins the matching kernel commit;
update that pin together with intentional kernel UAPI changes.

## Library Discovery

The bindings search for `libsparklink.so` in the following order:

1. `LIBSPARKLINK_PATH` environment variable (absolute path to .so)
2. `target/release/` or `target/debug/` relative to the workspace root
3. System library path (`ldconfig`, `LD_LIBRARY_PATH`)

## Usage

```python
from sparklink import Adapter

with Adapter("/dev/sparklink") as adpt:
    info = adpt.device_info()
    print(f"Device: {info.device_name}")
    print(f"Count: {adpt.device_count()}")

    adpt.start_scan()
    while True:
        ev = adpt.poll_event()
        if ev:
            print(f"Event type={ev.event_type} handle={ev.handle}")
        break
    adpt.stop_scan()
```
