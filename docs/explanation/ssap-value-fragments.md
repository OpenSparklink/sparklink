# SSAP 值、报文与片段的边界

应用值、SSAP逻辑报文、DTAP数据报与DLI ACB片段有各自的预算。完整响应装不下一个
值时，本地数据库能存下它不代表对端已收到。当前开发路径复用唯一用户态Engine的
单值codec；协商分片序号后，才将规范化逻辑报文拆成多个SSAP报文。每个报文仍须
满足实际通道MTU，并可能再次拆成多个DLI片段。两层分片不能互相替代。

发送队列中的一个逻辑请求持有不可变载荷、片游标、原期限与安全约束。首片准入只
启动一次排空期限，后续片不续期；每片都重新经过同一Native fd、Grant和提交机制。
作者退出不会删除已开始的物理义务，过期后也不能继续新提交。软件准入、控制器
完成、对端协议响应和对端应用处理仍是不同阶段。

接收侧按请求、响应和更新的有序流分别缓存。首片固定完整内核收据身份、安全epoch及
期限，后续片不得替换它们。只有收齐且序号和控制位一致，完整请求才交给授权及
数据库；部分写入不更新属性。无事务号时不声称支持任意并发或识别所有迟到重复响应。

异常或到期的部分流会使该SSAP actor失败，保持同一连接不自动重新绑定SMTC；
其余controller和普通应用通道不通过这一actor清理。这个失败策略不等于自然硬件
恢复，也不承诺已经完成所有撤权、断链或最终引用交错的验收。

本地逻辑值预算仍为2042字节。read、UUID响应及verified-write逻辑PDU预算2047，
单项通知/指示因条目头多一字节，预算2048；不能借后者扩大普通写入预算。
ACK只在完整更新进入原调用者队列后表达接受，接收者退出不伪造应用处理。
片数预算15；16片计数的四位编码尚缺独立向量，继续明确拒绝而不猜测。
发现分片、无序号分片、事务号并发和完整故障处理仍需扩展。
标准字段与固定NearLink Host的方言存在差异，不把其私有能力位当作当前标准能力。

Layout的限定形式化检查直接调用生产布局计算，只证明所列整数、片数及偏移边界。
缓冲复制与完整重组检查含unsupported、超时或内存限制时仍为未证明；工具成功行
不能覆盖它们。真实交付还需准确artifact的双端USB证据和对端应用完整值校验。
