# sparklink-python

Python bindings for libsparklink, the SparkLink userspace library.

Uses ctypes to call into `libsparklink.so` (the C FFI layer generated by cbindgen).

## Requirements

- Python >= 3.9
- Matching C library built with `cargo build --release -p libsparklink`.
  Cargo produces `target/release/liblibsparklink.so`; `make install` installs
  the public `libsparklink.so` alias. Development discovery accepts both names.

## Installation

```bash
pip install -e bindings/python/
```

## Tests

From the workspace root, run the unit tests and ABI conformance checks:

```bash
cargo build -p libsparklink --lib
PYTHONPATH=bindings/python python3 -m unittest discover -s bindings/python/tests -v
```

The conformance tests require `cc`, `rustc` and the matching kernel source
checkout at `../linux`. To use another checkout, set `SPARKLINK_KERNEL_UAPI`
to its `include/uapi/linux/sparklink_ioctl.h` file. Missing compilers or a
missing header fail the tests; they do not silently skip ABI validation.

The tests compile the actual kernel C UAPI, public C header and Rust UAPI
types, and compare every Python structure's fields, sizes, alignments and
member offsets. A C write into a guarded Python connection-info buffer also
checks the SSAP and credit fields. These tests need no devices, Cargo package
downloads when Cargo dependencies are cached or an installed library. Negative
FFI tests load the actual cdylib against `/dev/null`, checking errno, null guards,
unchanged output and constructor fd cleanup. Static freestanding i386 compilation
also compares every generated C member/size/alignment with the canonical UAPI;
it does not claim a 32-bit library/interpreter runtime test. CI pins the matching kernel commit;
update that pin together with intentional kernel UAPI changes.

## Library Discovery

The bindings search for `libsparklink.so` in the following order:

1. `LIBSPARKLINK_PATH` environment variable (absolute path to .so)
2. `target/release/` or `target/debug/` relative to the workspace root
3. System library path (`ldconfig`, `LD_LIBRARY_PATH`)

## Usage

```python
from sparklink import Adapter

with Adapter("/dev/sparklink") as adpt:
    info = adpt.device_info()
    print(f"Device: {info.device_name}")
    print(f"Count: {adpt.device_count()}")

    adpt.start_scan()
    while True:
        ev = adpt.poll_event()
        if ev:
            print(f"Event type={ev.event_type} handle={ev.handle}")
        break
    adpt.stop_scan()
```

## Native selected registrations

`Adapter` is the legacy compatibility interface. `NativeAdapter` is a separate
kernel interface for privileged services and selected observation; ordinary
applications use slctl/D-Bus. It does not grant CAP_NET_ADMIN or bypass the
Managed/Diagnostic owner. Profile-zero legacy managers and Diagnostic raw
queries are not migrated by this addition.

```python
from sparklink import NativeAdapter

with NativeAdapter(index=0) as adapter:
    snapshot = adapter.snapshot()
    print(snapshot.generation, snapshot.flags, bytes(snapshot.address).hex())
    print(adapter.management_status().state)
    event = adapter.poll_event()  # None when quiet; full payload and explicit lost
```

The constructor selects an index on its own fd, probes generation (or requires
the supplied nonzero one) and never follows index reuse after unplug. Keep the
generation and actual snapshot flags; successful open is not Ready. Replug
requires a new instance. OSError retains kernel errno, including ENODEV, EPERM
and EBUSY. close is idempotent and serialized against ctypes calls, which release
the GIL. Retained event/snoop records are copies, not mutable cursor views.

`acquire_management(1|2)` returns a lease for that fd. `release_management(lease,
mode)` admits asynchronous cleanup; poll `management_status()` until Free before
assuming a successor is available. Closing an owning handle triggers kernel
cleanup. A lease copied to another fd grants no authority.

Submit complete `sparklink.structs.SleDiscoverySubmit` via `submit_discovery`;
admission is not completion. `discovery_result(request_id)` returns None for
absent/evicted, retains queued/pending records and failed terminal status/error.
It does not implicitly supply RF/board defaults or acquire ownership.

Use separate NativeAdapter instances for controller events and privileged
`poll_snoop()`. Both return independent complete records, preserve loss/sequence
and never fall back to the consuming legacy DLI queue. Call the relevant poll
method once **before** registering borrowed `fileno()` with epoll; do not close
that fd or change its affinity yourself. Mixing event and snoop modes is EBUSY.
Current native ctypes layouts require eight-byte alignment. On older 32-bit
interpreters that cannot represent it, native setup explicitly fails; the legacy
binding remains usable. i386 C layout compilation does not prove that runtime.

Actual C/Python kernel gates run in [WS73 support guest](../../docs/WS73_TARGET_ENVIRONMENT.md).
These are synthetic development evidence, never physical WS73/RF acceptance.
