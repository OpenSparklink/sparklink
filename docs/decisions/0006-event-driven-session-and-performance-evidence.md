状态：采用（2026-10-16）；调度改造、性能资格和 USB 优化尚未实现或验收。

历史 8 次 61 字节 38–44 ms 是功能样本，不能证明当前性能或全部延迟原因。

## 通知与原期限定时分离

目标：有可执行工作立即调度，无工作休眠。保留每连接唯一、串行 Session worker，
由软件入队、当前身份的可消费 RX、实际 NOCP 恢复 data credit、协商/关闭/撤权、
Down/退休及原期限到期触发。命令 credit、data credit、peer 流控、软件预算独立。
通知只提示重查生产状态，不授予 Ready、credit、Grant 或发送资格。

实现前固定以下契约，并由生产代码与相关模型核对：

- Runtime 注册项携带 controller/generation/lifetime 与受保护的 Session 引用；
  通知先在注册锁内取得临时引用，释放锁后只设置待办并排队，不在 USB callback
  或原子上下文执行可睡眠 Session 工作。
- 沿用 Host→data→gate→Session 的准入顺序；通知注册锁不能形成反向依赖。
  具体注册锁、引用和调用图须随实现提交映射，不能把此设计视为已验证锁序。
- 单一待办序号/位图在与 worker 休眠决定相同的同步域中更新。worker 清理通知、
  检查可前进状态并决定休眠；退出前重检，事件到达运行/退出窗口必须再次调度。
  重复通知合并。queue 返回已排队与真正失败区分；失败不得遗留虚假 pending。
- 即时工作与独立 deadline timer 分开；timer 指向最早原协商、发送、重组或清理期限，
  中间片、重复通知及重排队不延长原期限。禁止把 10 ms 改为 0 后无限自排队。
- 停止顺序：身份失效并停止准入→撤销通知注册→排空通知临时引用→同步取消 timer／
  join worker（不持 worker 需要的锁）→清理物理义务→最终释放。未 drain 不 Free。
  与部分初始化回滚、在途提交、callback 排空同批验证；另一 controller 不受影响。

每轮有包数、字节数和执行时间预算。仍有可执行工作且耗尽预算才重排；无 credit
等待真实事件。通道轮转、防饥饿及 PB 分片连续性兼顾，不能在同连接 PDU 中错误交错。
预算具体数值先作为可测实现参数，不冒充硬件最优值或实时调度保证。

同步transport的时间上限不能由worker软件预算推导；预算只限制下一次操作的
开始。失败尝试也收费，真实credit阻塞后的旧进展不再表示当前可发送。观测分别
关联软件准入、出队、实际原子提交及同步返回；操作退休不能命名成对端完成。
序号分控制/业务命名空间，回绕或丢失时拒绝完整关联，未插桩分支明确排除。

## 发送及 USB 分期

先测旧路径，再消除轮询等待，再有界连续推进。每次实际提交仍经过原 Grant、
generation/lifetime、原期限与 Ticket 的原子门禁。USB 成功不归还协议 credit；
确定未提交和不确定失败分别记账，作者取消不抹去物理义务。

TX 预分配、多个在途 URB、HCC 聚合分别作为测量后的优化；需要独立的有限资源、
缓冲区/callback 所有权、取消/drain、顺序、短包尾延迟与公平性门禁，默认不启用。

WS73 当前一只 bulk RX URB：completion 内解析 aggregate／生产 ingress，随后重新
submit；notification URB 是另一用途，不能算第二个并行 bulk RX。首先记录 completion
到重提交、解析/ingress/锁竞争各段耗时、完成长度、突发流量与重提交失败，比较完整
追踪的扰动。空窗不预设为瓶颈。只有测量支持才缩短 callback 或引入有界多 RX URB。
多 URB 必须证明 controller 包顺序（含完成乱序与 aggregate 边界）、旧 generation
拒绝、每 buffer 唯一所有者、部分提交失败和 stop 后禁止重提交，join 后才释放。

首轮只读 RX 观测使用同 guest usbmon 的 completion→下一次同 URB submit，必须先
独立重放该次 Native 应用/两端 USB 证据，再限制到 start→双方 Quiescent 的区间。
该间隔包含 callback、USB core 与 VM 调度；不能作为 callback CPU 分段。多 URB
的决策仍依赖饱和/突发与观测扰动测量，低负载微秒级空窗不证明不存在饱和瓶颈。

失败负载也可保留只读间隔观测，但必须走显式失败诊断入口，绑定原请求及明确失败的
完整关闭快照；默认成功门禁入口不放宽。整个实际负载窗口及边缘截取单列，不能
手选窗口或把诊断退出成功升级为业务资格。某轮微秒级观测只能约束该轮解释，
不能证明所有负载无瓶颈，也不能替代callback分段、stop/drain或多URB所有权验证。

报告明确声明的证据等级与其结果、范围、源码和门禁一样属于绑定契约，摘要不能
独立重分类。未声明该字段的历史报告保持原限定范围，不能据此宣称已完整复核。

SSAP双向并发复用现有SDK和唯一Engine：同一有限子进程监督器支持单次或两个
独立controller调用，原启动屏障齐备后共同释放，共享原始监督期限。普通业务负载、
服务发现、UUID与Owned审批／清理不移出或删减；双向原件必须额外证明两个实际
请求都已提交且第一个完整回复尚未收到。它验证更强的双端在途行为，保留原顺序
场景及其失败，不通过调整顺序场景负载／期限来取得PASS，不新增Host或Wire Engine。
具体当前结果归唯一资格入口，原始逐轮观测归证据，不在此维护第二份能力矩阵。

## 性能证据与验证

使用普通应用的现有通道 socket，管理授权可经 slkd，逐包不走 D-Bus。三个负载及
时间线/报告契约见[指标参考](../reference/socket-benchmark.md)。固定随机输入在计时前
准备，热循环不用逐包日志、hex 或落盘；有界证据溢出必须计数并使完整资格失败。
完整追踪与低扰动测量分别运行。USB/HCC 不能单独量出 RF；没有时钟映射及误差界
不报告跨域单向时延，不用 RTT/2 代替。NOCP 不等于应用交付。

TLC/LKMM 处理通知/休眠、发布、引用/drain/关闭及唤醒，Kani/CBMC 直接验证适用
生产纯转换与 credit/预算。每份报告绑定源码、锁/线性化点、工具、边界、假设、
反例和实际回归。调度公平性、NOCP/固件行为、USB callback 排空不作为默认事实；
unsupported/timeout/未展开均未证明，模型通过不等于实现 refinement 或 RF 性能。

性能阈值待同配置重复基线稳定后设定；正确性不能由 goodput 抵消。不承诺 1 ms／
125 µs。正常/性能/调试镜像分别绑定，不放宽原期限。实验驱动与真实 WS73 全在 VM；
自然 RCA／非人工恢复继续开放，QMP、人工拔插、hub 切电与注入不替代自然恢复。

参考固定 NearLink Host f0872dfa 的 DTAP_SendCompleteCbk→SchedulerRun 与 libws73-usb
f4d85d0e 的 ACB pool gate，解释 SDK111 封装/调度差异；handle/count 回调不能证明
Linux lifetime 复用安全，也不把参考实现当性能裁判。


## 应用工具入口（2026-10-16）

应用正确性、ping-pong、绝对速率、有限窗口、双向与应答端统一归入独立
`slktest channel`，定位参考 BlueZ l2test；这是工具组织决策，不采用其协议实现。
`slctl` 保持管理、连接与授权。旧测试入口删除，不承诺未发布工具的兼容期。
迁移同一份循环/codec/报告实现至内部库；抓包、内核 selftests、形式化和资格聚合
继续使用现有设施。该迁移时的测量仅限基本 CUTC；后续动态负载入口的新增边界
按下节决定，历史资格不会因入口扩展而改变。

新二进制必须记录独立源码、artifact 与执行身份。历史报告和 argv 不重写；schema
语义不变。离线与空 USB VM 的入口/本地数据报回归不能继承旧 WS73 或性能资格。
入口整改结束后继续 P1 双端证据与基线，再推进 P2 事件驱动，不追加控制面全集门槛。

### 动态负载入口扩展（2026-10-20）

复用已存在的应用 SDK 动态 fd 创建、唯一 Session 和同一 slktest 负载／报告实现。
不复制循环或 Engine；业务方向与主动／被动协商角色分别指定。请求端口／AID 与
fd 实际 TCID／MTU／MPS 分开记录，基本报告保持原形，动态请求采用有版本的可选
tag。应用报告一致只证明应用层闭包，实际端口必须由 CMTC 捕获另行关联；监督器
先见被动 Staged 再创建主动端，仍保留双端 Armed／start／Quiescent／finish 屏障。

入口和本地生产循环／parser 的限定通过不等于 Native 或新工具的 WS73 资格。
Native runner 的动态目标必须绑定类型化请求、来源／启动参数／Root闭包、实际
CMTC协商及双端业务证据，缺项拒绝，不将参数存在或本地 staging 视为成功。
原基本目标保持原报告形状；动态目标另记请求、协商信令及实际TCID，仍使用同一
普通应用进程、负载循环和有限收集器。先取得单个动态测量对的纵向闭环，
再扩展多通道和四设备，不为这一扩展
等待所有控制面组合。原 credit／Ticket／Grant、期限、权限和失败断言不放宽。


## schema2 测量结束与报告隔离

关闭隔离使用同一监督器、SDK和schema2循环的显式版本3目标。全局启动屏障不变，
但每通道双端Quiescent后可单独finish；必须先回收短端进程，再以真实CMTC关闭和
其后新的长通道对端校验回复证明隔离。旧版本2的全局结束屏障保持原契约。短端
报告写出和回收发生在长业务期间，这项正确性场景不属于低扰动性能基线。进程
退出和CMTC确认均不升级为引用／callback排空、安全复用或自然恢复。

负载循环之后先发布Quiescent并保留fd，监督器核对双端均停止测量才发送finish。
结束等待保持独立原30秒预算；EOF/错误/超时记录于finalization，保留原drive错误和
全部计划行。该等待不延长消息期限，不算应用RTT/active_elapsed，不证明远端应用
已处理其它业务。资源端点仍明确包含采样开销；大规模hex/JSON延至双端结束授权后。
当前内存中的“结束成功”只表明收到本地控制输入；双端顺序须由监督器证据证明。
独立应用报告核对与artifact/凭据/USB捕获/监督器闭包分层，始终不授予性能资格。


## 调度变化后的受控生命周期测试

加快调度会使依靠固定sleep的撤权测试在撤权前发完整个PDU；这属于未建立测试
前提，既不能当撤权失败，也不能当验收通过。受控门禁先用既有有界真实IN暂缓，
以实际满池和未完成PDU状态建立因果屏障，再执行原撤权/关闭/断链动作并释放原
完成。原“未完成前缀、撤权后不提交”断言及原期限不放宽，host/guest各自时钟仅
按同域排序，用ack收取连接因果。直接Disconnect提交与本地Down观察区间单独
记录，不能把前者当已证明的实际发送屏障。旧失败、反例和未运行项不被重跑覆盖。
有界暂缓是注入环境，不能授予自然故障或非人工恢复资格。


## 就绪提示、原期限与重试分类

RX 就绪以“完整 PDU 成功进入 Runtime 有限队列”为准，不以每个 PB 分片到达为准。
原重组器返回是否实际入队，首片／中间片及丢弃不新增就绪提示，也不清除原提示；
NOCP、安全、撤权及连接变化保留独立通知来源。该判据不创建新队列或 worker，
不改变 generation／lifetime、重组预算、原期限、FIFO 或原通知引用／排空契约。
必须以生产入口检查完整入队、部分片、拒绝、满队列恢复及待处理提示，再以准确
新镜像的真实双端分片业务与生命周期回归核对；不从 fixture 推导并发／分配证明。

唯一Session同时持有就绪work与最早原期限的排队引用。Open且无待办或期限时
不排维护轮次；排队新事件只能提前，不能推迟已有较早期限。实际data reserve因
池满失败才标为CREDIT，等待真实完成提示或原期限；准入预检查和驱动EAGAIN
单独标为RETRY，在原期限内有限重试。USB完成不归还协议credit，不确定提交
仍保留物理debt。失败原因沿既有Ticket边界返回，不再增加另一套发送状态机。

每轮最多处理16个RX并考察六个通道槽。初期每槽推进一片；连续TX阶段改为
统一8次尝试/4096字节/下一调用前2ms预算，PDU完整边界轮转。有可推进工作才立即
重排，真实credit阻塞不能沿用同轮早先进展继续空转。已开始PDU保持PB顺序，但不能阻止其他未提交队列或待发拒绝按
原期限终结，也不能把已过期控制项反复排成零延时空转。有限轮次不是调度公平性
的完整证明；真实credit提示、关闭和drain仍需生产对应及VM交错验收。

真实 CREDIT 等待表示尚未获得服务，不能仅因空池探测就轮转尚未提交 PDU 的
通道。保留该候选轮次，等待真实完成提示或原期限；成功完成 PDU 后再轮转。
非 credit 的 RETRY 保留其既有策略，已开始 PB 的连续性不变。过期／撤销仍须
清除不可准入项并允许其他通道前进。轮次选择不预留 credit、不退款、不授予
提交资格；每次实际提交仍经过原身份、Grant、期限及 Ticket 门禁。调度器的
有限生产函数检查与真实有限负载结果分开，不能据此证明长期公平性、完成事件
真实性或所有引用排空。

控制项也必须覆盖实际提交观测：动态 CMTC 的准备、最终 consent 和同步返回
沿用同一 Session 观测序号。观测编号不作为 wire 事务号或协议成功条件。完整
trace／USB 关联保留所有接受包的数量、次序、长度及 consent 检查，不通过过滤
未覆盖控制包取得通过；旧采集无法满足新范围时保留其拒绝结果。

已闭合应用报告和载荷可在控制流程失败后作局部诊断，但必须复用原匹配器并
使用无法通过完整 finalizer 的独立结果类型。诊断不得补造 daemon-after、延长
Down 原期限或把 ABORTED trace 改为完整观测。完整控制、业务、追踪、性能和
恢复资格分别记录；一个局部正向结果不能覆盖整轮失败。

直接Down的受控前提使用四条真实单向短消息占四份未支付debt，长PDU使用余下
一份；对端逐条校验这些短消息。收到对端Down后才释放源端真实NOCP，使原
不完整前缀断言可被检查。它不证明Disconnect请求就是本地发送线性化点，不替代
原期限或自然恢复。TX状态ACTIVE是位1、BEGUN是位2；没有活动PDU时flags为0，
不能把ACTIVE误作状态有效或Ready。内核生产契约及原失败都保留。

限定的空闲观察使用VM内独立ftrace实例，只跟踪实际sl_work；两端实际排空快照、
业务前后正对照、唯一时间标记、CPU无丢失统计缺一不可。旧轮询镜像必须被同一
观察器拒绝。有限区间无调用不等于无竞态、总体空闲CPU或性能承诺，结果只从
唯一资格入口引用；历史TLC、LKMM或先前实机结果不自动升级到新源码。


## 以分段证据约束发送预算

不同应用窗口改变了排队负载，不能当同口径优化前后；角色分组和所有尝试都须保留。
xHCI关闭仍有usbmon/QEMU等开销，不是“无观测”基线。USB完成到下一提交的间隔
包含多个软件/设备层，区间内出现NOCP也不自动证明credit等待。增加连续发送预算
前，实际Session就绪/等待分类与服务轮次应可对应捕获，观测只读且不改变授权/记账。

预算分别限制包数、字节及开始下一操作的 elapsed；已有同步USB调用可能阻塞，
不能把检查预算等同整个worker已满足微秒级WCET。每片原期限、身份/Grant及提交票据
仍在真实提交边界核对，PB必须完整后才跨通道轮转，物理debt不因预算/退出消失。
原始请求的容量和实际分配分记：依内核真实页payload向上取整，再按读回单位核对；
不凭经验常量或任意容差接受。配置整数类型同样严格，历史检查器/执行身份不重写。


## VM 专用 Session 观测的失败封闭

独立默认关闭的实例记录生产 worker、软件队列及 Native 实际提交阶段，不采业务
载荷或密钥。启用必须由私有 scratch/QEMU/显式参数共同约束；退出停止、保存原件、
禁用事件并删除自己创建的实例，部分初始化也只清理自身资源。序号不是授权身份。
原业务和两端USB门禁先通过，才能关联 controller/generation/lifetime、不可变原期限、
预算和PB顺序。未开始PDU的EAGAIN重排与已接受但返回失败分别记账；退休不等于交付。

mono/realtime采用采样夹逼的共同偏移区间，不将USB墙钟与应用/trace单调时钟直接
相减；时钟无共同区间即失败。原事件格式、boot、容量读回、标记、CPU计数、条数和
hash必须闭合。首次实测1MiB/CPU长包突发覆盖9147条，整轮失败保留；按25188条
实际需求有界调整2MiB/CPU，文本仍最多8MiB且所有丢失均拒绝，不放宽协议期限。

这个采集器不包括动态CMTC的独立consent分支；暂拒绝该组合，不声称所有生产
路径均已追踪。观测与USB提交关联不是NOCP真值、callbackdrain、业务可靠性、性能
收益或实现并发证明。当前限定实机身份和后续成本/公平门禁只由唯一资格入口维护。


## 并发负载与最终释放的证据边界

并发门禁要求真实动态通道全部协商后，四个普通应用以同一个既有有期限输入解析器
等待启动；协调不授予Ready/credit，也不刷新协议或已准入PDU期限。短PDU在长TX
流中间完成发送只证明有限负载交错进展，不能升级为全部已准入队列的饥饿上界。

最后fd释放可以结束应用对象，但CMTC关闭和此前USB/NOCP物理义务仍归Session/
Runtime。观察窗口必须以明确的关闭/排空状态屏障封存，不能因应用成功、析构返回
或经验sleep而宣布debt清零。真实原件缺最终清偿即保留FAIL；晚到NOCP是定位线索，
不自动证明计数正确、回调排空或固件状态清除。相关屏障整改与独立数据交付并行。


## 关闭后观察边界补充（2026-10-17）

保留动态 burst v3 的最终 debt 失败。应用退出时间不能代表 CMTC 关闭及控制器完成
已收敛。采用授权只读 Session 快照与原独立 USB/NOCP 核对，在第一次 close 前固定
诊断期限及采样预算；只按首个实际满足精确终态的两端快照封存 v4 边界。
拒绝用任意固定睡眠延伸捕获窗口。该观察不改变原协议期限、不归还 credit，也不
作为 callback/ref drain、NOCP 真实性、Free 或 handle reuse 屏障。


## 同配置对照与负载请求（2026-10-17）

Native runner 将已有slktest的count/bytes/window/interval完整透传并绑定双端配置，
保留原schema2、软件/协议预算区分和失败语义。原固定20×61记录保持身份；新参数
不直接授予实机/性能资格。USB核对以完整frame键建立索引时保留所有重复候选，仍
要求每腿唯一匹配、所有CUTC业务完整归属，避免扩大负载后反复全表扫描。

bfaa与14d9的相同Kconfig、U42字节相同二进制、同执行工具/QEMU/SDK111及U2/3可
作为整体版本对照。源差异包含有界连续发送、tracepoint及发布锁，不作单一变量因果
推断。先有限平衡重复、分物理角色观测，之后量化同内核追踪开销和资源；USB捕获
自身仍有开销。未测量峰值、长期公平/恢复和完整性能资格保持缺失。

### 测量应用角色与证据归属

管理和建链仍由管理角色执行。规范的 VM benchmark 应用路径复用既有固定程序监督器，
以独立 apps-only UID/GID、空补充组和零 capability 运行实际 slktest；不把管理权限作为
业务 fd 收发的前提，也不新增 Host、协议 Engine 或收发循环。历史控制角色结果保留
原身份，不能改标为 apps-only。生产测量报告的 schema2、窗口含义和原始期限不变。

测试应用拥有报告文件，监督器在生产者退出并关闭文件后封存报告、完整日志和快照。
源码、准备镜像、启动选择器、角色凭据、文件归属和双端业务／USB 证据分别校验。
闭合文件、协议 ACK、NOCP 或 Root 监督器本身都不能代替对端应用处理。文件／VM
预算按测试配置记录，超限失败并保留原件；有限角色／测量闭包通过不升级为稳定
性能、完整压力、部署或权限生命周期资格。当前资格仍只由唯一能力入口中的准确
源码及 artifact 记录表达。

### 单 RX URB 的优化依据

先复用现有 xHCI observer，以明确的 mono 时钟和连接业务阶段边界测量 giveback
到重新进入 enqueue 的间隔，再决定是否缩短 callback 热路径或引入有界多 URB。
该间隔跨越 USB core 分派及提交准备，不能等同于 callback 本身或硬件接收空窗。
URB 指针只在单 boot、单连接阶段内关联，连接身份来自已有双端门禁；阶段边界的
未完成配对保留为 censored。开启／关闭追踪需要同 artifact 的有限重复对照。
这些观测不改变接收顺序、Runtime generation、buffer 所有权或 stop/drain 契约，
也不把尚未测得的瓶颈当作已确认的根因；多 URB 与异步 TX 仍是单独的后续决策。

### 共享 SSAP 的慢消费者门禁

复用唯一 Engine 与现有每租约有界 Queue／Sink，不为压力测试创建另一条发送或
接收路径。一个队列满不阻塞其他匹配接收者；指示 ACK 按至少一个有效队列准入
生成，各租约独立保留丢弃／拒绝计数，应用交付仍由实际校验及不同载荷回写证明。
有限 shared-pressure 场景要求慢端有序排空及恢复、健康端持续交付、部分释放与
最后引用线上停用，不能用单租约压力或无溢出共享资格替代。该负载含逐条服务观察、
报告及 SDK 交互，只用于正确性，不能作为低扰动吞吐／时延或完整公平性资格。

### 服务与通道并发先证明实际交叠

既有共享SSAP队列隔离与顺序执行的普通通道基线，不自动证明两类业务同时运行。
显式并发场景复用原SDK服务／审批／值检查和slktest循环，分别保留权限与身份，
由同一物理Session按不同TCID分流。只有双端实际载荷及应用结果在同一guest USB
窗口前／中／后均闭合，才授该有限并发切片；Root调度标记不制造业务进展。
共享子进程收据在快照中只转换一次结构化路径，原始stdout和旧路径拒绝规则不变。
新场景含服务启动、审批和IO，不授低扰动性能、公平性或完整生命周期资格。

### 双向 SDK 请求与并发证据

双向服务请求和普通通道负载复用同一 Engine／物理 Session。测试监督器只管理
真实 SDK 调用的有限子进程与原启动屏障，不承担协议或制造完成；一组调用共用
首次释放时确定的原期限。请求同时在途须核对实际两端请求末片 USB TX 与首个完整
回复 RX，不能从进程并发推导空口同时发送。原顺序场景、独立保持回归与新并发
场景各自保留请求、负载、终态及证据身份，不互相替代。当前资格由唯一能力入口维护。

有限监督器复用一个单／双子进程实现与同一个值事务循环。双调用只在显式 VM
场景开放，两端全部真实启动屏障到达才释放；等待使用第一次释放产生的绝对期限，
不得为第二个调用重置。真实SDK各自拥有授权、身份与物理会话，请求末片TX／回复
完整RX的可观察窗口只证明USB请求在途，不分离固件或RF时延。原单次入口保留原
调用顺序与所有结果检查，须通过独立实际入口回归；新双向通过不修复另一原顺序
满负载失败，亦不升级为性能、公平性、完整生命周期或安全资格。


### 失败追踪不得制造闭合

原整轮失败、完整成功追踪与失败诊断使用不同入口。诊断共用实际文件、事件和 USB
关联检查，保留整个输入及所有入队对象；没有观察到的退休端点以未知表达，禁止
过滤对象或填零来闭合。已有完整追踪／业务验收继续拒绝这些缺口；分析命令执行
成功不代表门禁通过。队列清除没有对应事件或追踪先于清理结束时，不能据此推断
内核对象泄漏、Free、引用排空或 credit 已结清。必要观测与改进按其准确源码另设门禁，
不延长协议期限或改变业务负载来消除原失败。


### 排队清除与物理义务分开观测

生产队列清除复用同一个helper：在原TX队列锁下摘出有限列表，释放锁后发出独立
的本地清除终态并按原drop reason释放skb。它不触及Session已开始的PB操作、Grant、
Ticket或Runtime的debt，也不增加controller完成。所有清除调用者统一迁移，避免
只有正常发送操作有终态而取消／释放队列无观测。

采集版本2明确区分stage3，分析要求零实际接受前缀和确定的未提交重试。旧捕获
按原版本保留未知端点，不能事后补齐。失败清理的追踪封存在所属进程停止尝试之后，
仍标ABORTED；完整对象／callback／USB排空须有独立证据，不从队列为空推导。

排队清除的实机门禁必须实际创建排队对象。显式测试场景在原已开始PDU后使用
同一普通用户受限socket准入两份独立随机PDU，原满池／前缀、撤权／dup／Down／
期限与同行控制门禁均保留。每次准入保持自己的原期限；撤权后的重试仍使用最初
已开始PDU的缓存intent，不用后续准入更新它。生产TX快照必须同时观察到原busy
对象和两个排队对象，追踪按完整身份和syscall单调时间窗唯一关联stage3及零USB
前缀。原已开始PDU的部分物理义务另外关联；本地丢弃、业务交付和全引用排空三者
不得互相替代。默认旧场景不隐式增加负载，带追踪丢事件仍失败，历史资格不回写。
