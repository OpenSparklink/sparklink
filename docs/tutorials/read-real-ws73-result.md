# 读懂一次真实双 WS73 闭环

完成这篇教程后，你能从已验证路径分辨控制请求、真实接收和业务回复，并为一轮结果填写身份与范围。无需设备、不执行旧镜像命令。

1. 打开 [当前资格](../../project/current-capabilities.md)，找到准确的历史实机源码对 `ae5b24535a89`／`967ad220`。它保留交换角色 40 轮短消息和 249 字节子门禁；不要把这项资格写到另一提交上。
2. 从该条目的证据链接找到控制请求及接收证据。对于发现轮次，记录两只设备身份、随机 marker、匹配数据、地址、RSSI 和期限。没有真实接收就没有发现闭环。
3. 对连接后的短消息，记录 controller generation、connection lifetime 和通道；核对对端应用实际校验随机序号／载荷并回复。USB 成功和 NOCP 不能代替这一步。
4. 交换发送方向时，继续检查独立对端结果，不将广播载荷当成连接后数据。
5. 将你找到的结果填写成表格：

| 项目 | 要填写的内容 |
|---|---|
| 源码与输入 | 两仓库准确提交、镜像与固件 provenance |
| 物理身份 | 两个 USB 端口、controller generation、连接 lifetime |
| 业务结果 | 随机序号／载荷校验、对端回复、交换方向 |
| 证据限制 | capture 是否可取得、丢包统计、未覆盖门禁 |

如果原始材料仅在私有工作区，写“摘要可审查，原始材料不可取得”，不要写“已重现”。你现在得到的是一份有明确边界的结果摘要，尚未执行新的硬件验收。实际准备参阅 [VM 回归指南](../how-to/prepare-vm-gate.md)。
