# ADR 0005：资格记录、分层测试与质量门禁

状态：采用（2026-10-15）；本次采用不表示下列测试、证明或发布门禁已完成。

## 问题与决定

审查基线 K8cbf53/Ueaea706 存在保留实机资格与旧“当前”字段并列、文档 CI 无法
检测语义冲突的问题。Agent dirty 接线保留。采用最小版本化
`project/qualification-records.json`，把契约、生产源码范围及 hash、编译产物、执行
工具、配置/固件、必需门禁、结果、限定范围与剩余条件连起来。
编译提交、执行工具提交与公开报告提交分开；文档提交不重命名旧镜像。

能力页、计划中的资格摘要及 goal 的 `qualification_view` 由该记录生成/校验。
废止独立维护的 current_heads/current_batch/current_batch_exit 等资格字段，原值存入
机器历史，旧能力页原文归历史。架构、唯一计划、能力页仍是各自 canonical 入口。
记录迁移为增量：本批封存21组与两项期限相关证明，其他历史报告不因此丢失或升级。

层级分别为 implemented/offline/formal_bounded/virtual_integration/real_device；
PASS/FAIL/UNPROVED/MISSING/SKIP 分开。某个必需项非 PASS 则整组不能 PASS。
unsupported、timeout、未展开/缺性质不得靠退出0、计数或其他局部 PASS 升级。
`INCOMPLETE` 的完整目标不会因保留21组或算术100检查通过变为完成。

完整报告矩阵中已知非PASS结果按名称约束门禁，不能通过删除单行pointer或版本字段
将其升级为PASS。旧记录可保守降级局部离线PASS，不能因此宣布更广集成通过。
新门禁采用 `result_binding_version: 1`：报告行的 `status` 必须是上述
五种结果之一，且与该门禁的 `result` 完全一致，未知版本拒绝。整体已经 FAIL
也不能放过局部标签漂移；例如将失败尺寸单独改成 PASS，或把报告 PASS 改为
UNPROVED，均须拒绝绑定。它不改变历史 opaque 状态记录的含义，也不将 metadata
检查升级为实测。原报告／源码／artifact 身份仍分别固定，失败记录不覆盖。

故障诊断可在原期限判FAIL并持久化后，显式增加有界的清理前被动捕获窗口；
它不能延长原期限、补写成功receipt或改变原终态。窗口应记录实际起止、命令数和
中断状态，按两端全部USB提交核对是否受其他流量混杂，不能只凭测试工具未发命令
推定总线静默。未复现时记录未复现及窗口未执行，不能用重复成功替换原失败或授予
根因、恢复、实机观察分支资格。工具源码、guest输入和编译生产产物仍分别绑定。

终态条件统一在所有runner模式入口检查：保存的PASS必须同时有整数零的QEMU与
supervisor退出凭据。只有producer内部计算尚未写出的supervisor结果时可明确pending，
已有失败不可忽略，记录字段不能启用该内部阶段。旧解析器接受异常退出的反例保留；
修复工具重放旧原件仅取得离线校验资格，不改写原执行身份或补填历史缺失凭据。

退出凭据只是终态条件的一部分。显式请求的连接、对象及通道证明不得从保存
报告删除；prefix-close 还须保留两个角色的关闭后真实 SSAP 证明。对端完成接收
与已关闭发送端收到回复分别计数。摘要门禁只查请求与保存结果的一致性，原始
双端捕获校验仍独立执行；完整原件通过不能掩盖删证后判定仍成功的工具缺陷。

## 材料与信任边界

私有生产者报告在metadata模式不可取得时，即使两个提交含有相同生产源码字节，
也无法据此确定artifact实际由哪个提交编译。依赖私有报告的编译身份、范围或结果
绑定负对照必须在local模式读取并核对原报告；metadata接受同字节提交别名只能记作
该模式未验证此身份，不能当作实际编译来源或当前硬件资格通过。公共CI的metadata
检查、可取得源码检查、完整local材料校验及实机门禁分别报告。

新报告可声明 `evidence_manifest_version: 1`，冻结其 `materials` 元数据。
对应registry必须提供 `material_binding_version: 1` 和完整的 `material_bindings`
映射：每个材料的路径、hash、大小、访问方式及来源元数据必须与报告一致，不能
仅重算registry里的新文件指纹就接替原材料。声明版本后不得删除绑定或退回legacy，
未知版本、缺映射、替换路径或已重新计算的不同hash均拒绝。metadata也检查这项
关联，仍不宣称私有字节已取得；旧报告不因迁移自动升级或改变原资格。

广告模式等配置也是资格身份的一部分。相同内核、固件和二进制不等于相同试验：
CLI请求与实际DLI字段须同时绑定。SDK110已封存Negotiable-T条件不能由Fixed-T
默认值代替，发现成功或Status0也不补足连接Outcome。独立对照失败保留，不自动
fallback，也不把改正测试配置称为已证明固件／自然故障的根因或恢复。

公开 CI 的 metadata 模式检查公开报告、scope、门禁身份、生成摘要和可取得的
源码映射；缺私有材料或兄弟仓库只得到 METADATA_ONLY_NOT_REVERIFIED，不能
授予当前实机 PASS。本地 local 模式核对全部原件的大小/hash/记录断言；缺失或
不符失败。`--require-current` 另核对声明源码范围的 tracked/untracked 字节，
范围变更即拒绝继承；保留旧资格仍只适用于旧源码。

硬件更换也是资格身份变化：记录每端型号、信息来源、拓扑和实际设备身份，不能
凭相同 VID/PID、端口号或启动成功推定板级/固件兼容。旧硬件资格与混合型号的
限定观察分开；中断批次保留中断状态，已完成子结果不能补足未执行的必需门禁。

完整性检查不是独立 RF 重解码、构建可复现性证明、实现 refinement 或重新执行。
它信任冻结报告及其已记录身份；范围外变化、编译器、Linux、库、固件和硬件
不因此被证明。后续每批新增能力必须登记自己的生产入口、fixture、边界、oracle、
环境、命令及源码/配置 hash，不能只加一个字符串 PASS。

含密钥捕获、固件和受限材料不入站点。记录相对保留路径、指纹、访问条件和重放
入口；当前无已验证异地保留保证。原件丢失时保留历史陈述，同时撤销可核对性，
不得声称当前 PASS。失败/反例/所有尝试保留，重跑不覆盖失败。

## 测试和实现的关系

复用真实生产入口及 Virtual/QEMU/selftests/private D-Bus/WS73，不另造协议 Engine。
提取函数测试显式列出锁/分配器/引用/USB/时钟 fixture，不升级为内核并发资格。
字节 fuzz、状态序列 fuzz、syzkaller 接口 fuzz 分层；真实恶意 USB/固件输入先在
离线/虚拟后端。每步查身份、credit、预算、终态及副作用，不只检查不崩溃；FFI
指针调用者 UB 不与内核 EFAULT 契约混淆。固定语料与长探索分别记录。

KASAN/UBSAN、KCSAN/lockdep、故障注入/泄漏、KCOV 分镜像，在 VM 中验证实际
插桩范围与路径执行；无报告不单独构成通过，不通过延长期限补偿调试开销。
组合性质直接映射生产转换、锁、引用与线性化点；NOCP真值/晚到重复、callback
排空、固件清除、调度公平性是待验证假设，不默认成立。

策略批准不等于认证/Bond；软件准入、USB提交、控制器完成、对端协议接收、应用
处理分别表达。system bus/组/udev/内核强制权限必须在真实 VM 部署验证，不能用
XML 或 private session bus 替代。一个 daemon 的 actor 不提供进程故障隔离。

## 实施约束与后果

只将当批改动相关性质作为门禁，质量工作随 Agent/数据/SSAP/多通道/四设备并行。
完整 S0–S6/19WP/10FV/12DG、旧路径、VM-only 不变，UserHost P4；不追加控制面竞争
全集前置条件。安装、供应链和长期运行依照唯一实施计划，构建 artifact 不默认
是合格发布。自然RCA和非人工恢复继续开放，人工/hub/QMP/注入不代替。

第一批退出：生成摘要一致、原材料核对与当前源码资格分开、故意旧源码/缺产物/
范围错配/必需失败或未证明均被检测。后续 schema 变更需显式版本迁移及负对照；
证明/模型和工具自身的 parser/verdict 也必须回归。

监督器输出在运行开始先原子替换为 RUNNING_NOT_QUALIFIED/completed=false，
完成后才原子写最终完整性结果；保存旧成功报告的路径也不得在异常退出后冒充新结果。
这项保护覆盖CLI完成参数解析后开始校验的阶段，不声称证明宿主文件系统或进程启动。

保留的执行脚本以 `source_commit` 从 Git 对象读取并核对 hash，不要求正在开发的
同名脚本冻结。当前源码匹配独立检查，不能凭旧对象授予新工作树资格。原始产物/
私有捕获仍检查实际文件；公开报告文件也继续核对，缺对象不回退到当前工作树。

公开报告的提交也单独验证：PASS/UNPROVED记录必须能在所声明Git提交找到完全
相同hash/大小的报告，不允许用编译源码提交代替报告提交。先封存报告blob，再在
资格记录中绑定该提交，避免自引用hash与多个“当前”字段独立更新。

## 有界生产 codec fuzz 的证据强度

pureC gate直接链接生产文件，观察callback/合法指针、真实libc分配和工具为显式依赖；
不使用另一个parser或假成功transport。固定/扩展corpus、种子、二进制、完整日志和
LLVM目标执行计数分别保留。sanitizer符号存在不够，实际路径必须执行；DONE文本和
退出码单独都不够，截断、masked失败、LSan环境失败、缺覆盖/源码变更均不能通过。
有界无发现只属于offline探索结果，不是长期不变量证明、kernel sanitizer、SSAP/
credit生命周期或实机资格。Clang版本/环境与改动来源单列，前序探索和反例不覆盖。
跨仓库CI pin必须随codec/harness评审更新；定时任务仅覆盖其准确pin，不暗称最新HEAD。


## 真实安装回复屏障（2026-10-17）

为区分准入前策略取消与安装已提交后的物理义务，测试设施允许按已捕获 SDK111
封装选择真实成功的安装 Status/Complete；完整 HCC 边界校验后保留原 transfer，
不生成事件、不改字节、不按帧序号或 sleep 推定安装。默认关闭，限定 attached
WS73 且 reset/detach 关闭，与帧 skip/错误注入互斥；复用原有有界释放/abort/drain。
聚合内其他事件一起保留，不能拆包或重排制造所需交错。选择 opcode 不提供
lifetime 身份，独立验收须核对原请求/作者/gen/lifetime/期限/实际提交票据、两端
捕获及原帧 hash；软件撤销不等于物理密钥移除或硬件未加密。离线 callback 测试、
暂停 QMP 属性与真实 WS73 三个层级分开，当前结果见唯一资格入口。新屏障本身
不证明取消/复用/密钥擦除/自然恢复，不替换原有失败或完整安全门禁。


安装后取消的 oracle 分层：持帧期间取得的原生取消快照、冻结的 daemon 请求终态、
真实迟到 USB 接受/加密事件和对端应用回复分别记载。终态后相同的 `kernel_*`
缓存字段不构成新的原 File ioctl、credit/ref/callback 排空或复用证明；原请求
取消也不保证物理安装回滚。原门禁有这些缺口时继续记未证明，不能以缓存不可改写
替代内核与硬件组合性质。命令 credit 与数据/peer 流控预算仍独立。

2026-10-17状态入口收敛：结构化记录的`selected_qualification`采用version1和record引用，
只选择一个准确的保留产物，不授予当前工作树整体资格。选择无效/未知/已退休记录、
额外结果字段或错误类型必须拒绝；源身份由原记录生成，不在文档独立维护。
全部历史PASS、FAIL、UNPROVED和required范围继续可见，整体结果不因选择局部PASS改变。
旧能力入口原文以提交/hash保留在history，仅当前canonical页表达当前边界；历史基线
标为历史。文档/goal视图仍由同一记录生成/校验，公开CI元数据不等本机重放或硬件资格。

架构执行状态中的qualification_reference也只指向生成的selected_qualification，
不再独立复制compiled source IDs。嵌套旧source/record或额外PASS字段必须拒绝；
write-views不能悄悄覆盖这类独立资格声明。此守卫仅检查明确结构字段，不声称能
理解所有手写叙述或历史证据；原失败与限定范围仍保留。


退休接口的测试依赖也需迁移：历史布局不能继续依赖默认公开头中的旧类型；
历史suite保留精确源码/hash及原运行身份，停止作为当前推荐命令。当前数值/声明
检查、日志assessor负对照、实际VM syscall与真实WS73分别记录，编译通过不证明
所有历史场景已迁移。共享事件“排空”迁到作者隔离的typed结果后，应验证另一作者
不能获取旧结果，不沿用不存在的队列计数。模型或历史测试不得制造新当前资格。


选定PASS记录的bounds必须用`report.bounds_pointer`绑定不可改写的公开报告；当前计数与
源码/层级一同自动生成到计划和能力入口，不另维护手工“最新资格”表。缺少映射、
报告/registry边界不一致或生成段残留旧计数均拒绝。历史记录保留原schema和限定范围，
不借此补写旧数值或升级旧资格；计数自身仍不是门禁或实现证明。

权限夹具必须使用实际调用者的内核凭据，不从文件mode、root名称或fakeroot返回值
推导访问结果。root可能读取mode000；需要权限拒绝时，真实运行未授权读取者并保留
原拒绝/无fallback断言，不能SKIP用例或给生产解析器新增人为限制。普通用户CI通过
不能替代root包构建/实际部署，UID/GID、capability与平台元数据fixture须明确记录。
包构建的版本依赖由真实编译器/库满足；实验工具链包必须包含实际payload与许可证，
不能用空provider或跳过依赖取得通过。平台include的dry-run替代仅是离线源码检查，
完整构建、实际安装、升级回滚、内核权限及实机验收分别记录。

固件证据范围由新物理 runner 调用者显式选择：运行态观察和逐 Runtime 上传门禁
分别表达。原始 USB 成对读取器、镜像核对器与 HCC 核对器统一复用，USB-core 日志
提供固定 guest 路径的实例关系，不以 devnum 排序配对。缺一个 Runtime、后续暖态
接入、来源不匹配或未证明均不能通过严格门禁；普通业务结果独立保留。该组合依赖
同一 VM 的完整封存输入及 QMP 路径映射，不宣称执行认证或冷电源证明，也不授予
控制器权限、Ready 或自动恢复资格。历史解析器保留原行为，历史证据不补写新标志。
